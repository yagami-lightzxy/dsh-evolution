# 安全、供应链与回滚

## 1. 风险分级

| 等级 | 判定 | 授权 | 保护措施 |
|---|---|---|---|
| R0 | 只读、无副作用 | 不需要 | 不读取无关隐私；报告脱敏 |
| R1 | 可逆本地修改 | 任务范围内可直接做 | diff/备份；可回滚 |
| R2 | 受控配置/免费依赖/计划任务 | 说明后执行；默认 dry-run | 快照、最小改动、验证 |
| R3 | 删除/覆盖、外发、付费、提权、生产 | **明确授权** | 快照、审批记录、回滚演练 |
| R4 | 伪造、绕过、窃密、不可逆破坏 | 拒绝 | 说明原因与安全替代 |

不确定时按更高一级处理。

## 2. 安装第三方组件前的审查

必须检查：
1. **来源**：官方仓库/包管理器/可信发布者；避免短链、网盘、未知二进制。
2. **代码风险**：安装脚本、postinstall、动态下载、混淆、`curl|sh`、`powershell -enc`。
3. **依赖**：数量、许可证、是否固定版本、是否引入原生扩展/服务。
4. **权限**：需要读取哪些目录、网络、凭据、管理员权限。
5. **维护状态**：最近提交、issue 响应、归档标记、安全公告。
6. **许可证**：与当前使用场景兼容；保留版权与 NOTICE。
7. **回滚**：卸载方式、配置备份、数据迁移。

审查结论写入审阅报告或 `knowledge/decisions.md`。无法验证时**不安装**，给出替代方案。

## 3. 默认安全策略

- 默认离线；联网必须显式 `--online`。
- 手动命令默认 dry-run：install/uninstall/rollback/import/schedule/prune/fetch。
- 用户已授权 evolution 周任务自主维护：`maintain/review --apply` 可去重、隔离无效技能、同 major 升级、按需下载；仍受本节边界约束。
- 不执行被审计的代码；只做静态读取与哈希。
- 不读取/输出凭据、cookie、私钥、完整环境变量值。
- 密钥形态命中时：脱敏展示、建议轮换、不写入报告原文。
- 文件写入：临时文件 + `os.replace` 原子替换；保留备份。
- 并发：单实例锁；超时与陈旧锁清理；锁文件不删除他人活跃锁。
- 路径：拒绝 `..` 穿越、绝对路径逃逸、指向根目录的删除。
- 导入包：校验 manifest、SHA-256、版本、文件数量/大小上限、符号链接。
- 计划任务：只注册当前用户任务，不请求管理员；命令使用绝对路径；可一键移除。

## 3.5 插件升级的执行边界（v1.3.0）

- 只通过宿主 CLI 执行（dsh plugin --profile <p> add <name>@<ver>），不手工编辑 node_modules 或锁文件。
- 只升级同 major 的注册表版本；跨 major、link:、github: 依赖永不自动改写。
- 每次升级前 snapshot，并备份 profile 的 package.json 与 pnpm-lock.yaml。
- 逐项校验安装后的实际版本；任一失败即整批回滚并重新 install。
- 升级写入后必须重启宿主才生效：报告要标 requires_restart，不得宣称"已生效"。
- 宿主自述不兼容的插件，优先升级或卸载；显式豁免需要单独命令并记录理由。

## 3.6 自主性边界（v1.5.1）

默认执行，而不是请示。可逆且证据可核的动作，直接做完再报告：

- 环境体检、技能健康、锁文件与依赖一致性检查；
- 补装或重装"已声明但缺失"的依赖，同步锁文件；
- 同 major 的插件/技能升级（先快照，失败回滚）；
- 修技能引用、补测试、重新 verify；
- 断舍离白名单内、宽限期外的缓存与过期产物。

必须停下来先问：

- 删除或覆盖用户手写内容；卸载仍在使用的插件/技能；
- 跨 major 升级、外发数据、付费、提权；
- 同一命令连续两次失败后的第三次尝试（先定位根因，不盲目重试）。

报告格式固定为：做了什么 → 证据（命令、版本、校验和）→ 回滚路径。
"需要用户确认"不是默认答案；只有命中上面第二组才成立。

## 4. 危险模式（静态扫描）

### 脚本
- `curl ... | sh` / `wget ... | bash`
- `powershell -enc` / `-EncodedCommand`
- `rm -rf /`、`Remove-Item -Recurse -Force C:\`
- `eval(` / `exec(` 结合 base64/动态下载
- `subprocess(... shell=True)`、`os.system(...)`
- `chmod 777`、关闭 SELinux/防火墙
- `git push --force` 到 main/master
- `--no-verify`、跳过签名/校验

### 配置
- 明文 HTTP 远程端点
- `npx -y` 未固定版本
- MCP 服务使用 shell 拼接、读取宽泛环境变量
- Agent 权限 `danger-full-access` + `approval never` 长期开启
- 自动批准所有工具调用

### 凭据
- `sk-...`、`ghp_...`、`AKIA...`、私钥块、`password=...`
- `.env` 被加入版本控制/导出包

命中只作为**信号**，需人工确认；报告不得包含完整秘密。

## 5. 回滚

- 变更前 `snapshot`；记录文件哈希、配置、受管块、调度状态。
- 回滚前再快照当前状态（避免回滚丢失新改动）。
- 回滚后运行 `doctor` + `selfcheck`，核对哈希。
- 无法回滚的变更（外部服务、已发送数据、已付费）必须提前说明。
- 删除类操作先移到 `backups/` 或回收站，保留至少 7 天。

## 5.1 自主维护边界（2026-11-07）

允许自动执行：
- 同内容技能去重：保留规范源，其他位置改为 junction/symlink；备份原目录。
- 无效 frontmatter 技能：移到 `state/quarantine/`，保留 manifest，不永久删除。
- 同 major 的插件/技能升级：升级前 `snapshot`，失败恢复；跨 major 只报告。
- `config.maintenance.install_queue` 中的按需下载：来源/许可证/静态扫描通过后安装；备份旧版本。
- 自升级：仅在有新学习项时更新自身版本；先 snapshot，跑完整测试；失败恢复 VERSION/SKILL/CHANGELOG 与代码版本号；发布包保留哈希。

必须停止并报告：
- 付费、外发敏感数据、跨 major、未备份删除、删除用户手写技能。
- 任何 `critical` 审计发现；不可逆或无法回滚的操作。
- 第三方插件安装/升级失败两次；不要循环重试。

每轮维护写 `state/maintenance-latest.json` 与 `reports/maintenance/`；周报列出已执行、失败、回滚点。

## 6. 事件响应

1. 停止进一步操作，保留现场（日志、哈希、命令历史）。
2. 评估影响范围：数据、凭据、外部系统、其他 Agent。
3. 隔离：禁用相关技能/MCP/计划任务，不删除证据。
4. 修复：轮换凭据、回滚、补丁、加检测。
5. 复盘：根因、防复发、规则/测试更新；写入 `knowledge/lessons.md`。
