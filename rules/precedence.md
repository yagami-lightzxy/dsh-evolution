# 规则优先级与冲突处理

## 1. 优先级（从高到低）

| 级别 | 来源 | 说明 |
|---|---|---|
| P0 | 系统安全、法律、平台硬限制 | 不可被任何规则覆盖 |
| P1 | 用户当前明确指令 | 本轮/本任务的明确要求；与 P0 冲突时以 P0 为准 |
| P2 | 项目规则 | 项目 `AGENTS.md`、`.dsh/`、仓库约定、CI 配置 |
| P3 | 全局 evolution 规则 | 本目录 `rules/` 与 `AGENTS.md` 受管块 |
| P4 | Agent/技能默认 | 技能正文、平台默认配置、工具默认行为 |
| P5 | 任务级覆盖 | 临时参数、实验分支、个人偏好 |

**近者优先**与**严者优先**并用：
- 同一级别内，更具体、更新、更接近当前任务的规则优先。
- 跨级别冲突时，高级别优先；若低级别更严格且不违背高级别，按更严格者执行。
- 安全、授权、验收标准只允许被收紧，不允许被任务级覆盖放宽。

## 2. 常见冲突

### 项目要求“跳过测试快速交付” vs 全局“必须验证”
- 若项目规则明确且用户授权，可减少**非关键**测试；关键路径验证不可跳过。
- 必须在交付说明中写明跳过了什么、风险是什么、如何补验。

### 技能要求“安装最新工具” vs 全局“不盲目升级”
- 先验证收益、兼容性、许可证与回滚路径；默认不自动升级。
- 需要安装时先 dry-run，涉及付费/敏感权限先获授权。

### 用户要求“删除旧组件” vs 安全“不可逆操作需授权”
- 先列出影响范围、依赖关系、备份/回滚方案；得到明确授权后执行。
- 无法确认依赖时，只归档不删除。

### 两个 Agent 的规则不一致
- 以共同的高级规则（P0-P2）为准；把差异写入 `knowledge/decisions.md`。
- 不能消解且影响实质结果时，向用户提出一个合并问题，附选项与影响。

## 3. 任务级覆盖的记录格式

允许的覆盖必须可审计：

```yaml
override:
  rule: "默认联网检索"
  value: "本轮离线"
  reason: "用户要求不联网"
  scope: "task-2026-11-04-001"
  expires: "task-end"
  risk: "可能缺少最新信息，交付中标注"
```

禁止的覆盖：
- 跳过授权/审批
- 隐藏或伪造验证结果
- 扩大权限、外发敏感数据
- 删除备份/审计日志
- 关闭安全扫描后仍宣称“已审查”

## 4. 决策记录

重要冲突与取舍写入 `~/.agents/evolution/knowledge/decisions.md`：
- 日期、场景、冲突规则、选择、理由、证据、复审日期。
- 只记录有跨会话价值的决策；一次性偏好不写。
