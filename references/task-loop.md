# 任务执行环：检查表、决策矩阵与验收

## 0. 任务分级

| 级别 | 特征 | 默认路径 |
|---|---|---|
| S | 单文件、事实明确、可逆 | 直接执行 → 最小验证 |
| M | 多文件/多步骤、需检索、有集成点 | 盘点 → 计划 → 执行 → 集成验证 |
| L | 跨系统、长周期、多人/多 Agent、高风险 | 蓝图 → 拆分 → 并行 → 阶段验收 → 总验收 |
| X | 目标不清/高风险/不可逆 | 先澄清或拒绝高风险部分，拆分可做部分 |

不要为了“显得专业”把 S 级任务升级成 L 级流程。

## 1. 理解（Intake）

- [ ] 目标一句话；成功是什么样？
- [ ] 范围：必须做 / 不做 / 可选
- [ ] 约束：时间、平台、权限、预算、依赖、兼容性
- [ ] 验收标准：可观察、可复现、有证据
- [ ] 风险等级 R0-R4；是否需要授权
- [ ] 未知项：哪些能自行调查，哪些必须问

**只问一次**：把阻塞性问题合并；非阻塞的用合理默认并在交付中说明。

## 2. 盘点（Reuse scan）

按顺序：
1. 本会话已有工具/文件/上下文
2. 本机 Skill（`evolution capabilities`）
3. 本机 MCP / 插件 / CLI / API
4. 项目内脚本、配置、历史产物
5. 组织/团队共享方案

输出：候选方案表（名称、来源、适配度、维护、许可证、风险、成本）。**没有盘点就自建，视为流程缺陷。**

## 3. 检索（Research）

触发条件：能力缺口、方案不确定、需要最新事实、许可证/兼容性未知。

- 来源优先级：官方文档 > 官方仓库/Release > 标准组织 > 维护活跃的社区项目 > 博客/问答
- 评估：最近提交、release 节奏、issue 响应、归档、下载量/使用证据、依赖数量、许可证、安全公告
- 记录：URL、版本/日期、关键结论、适用条件
- 不把搜索摘要当事实；关键结论打开原文核对

## 4. 补全（Capability fill）

- 先判断“是否真的需要新能力”；能用现有工具组合解决就不装。
- 方案排序：内置 → 已装 → 轻量脚本 → 成熟开源 → 自建
- 安装前审查（见 `rules/security.md`）
- 默认 dry-run；R3 需明确授权
- 记录：装了什么、版本、来源、许可证、回滚方式

## 5. 执行（Execute）

- 选择路径：质量/风险优先，成本其次
- 拆分：按可独立验收的单元；写冲突的任务不并行
- 并行：只对独立读任务/独立写域；设上限
- 缓存：对稳定、昂贵、可复用的结果；设失效条件
- 检查点：长任务每阶段留证据，失败可恢复
- 不做：重复搜索、重复读取、无意义工具调用、为并行而并行

## 6. 验证（Verify）

按风险选择：
- 代码：单测、集成、构建、类型/ lint、真实运行
- 文档：事实核对、链接、结构、渲染
- 数据：口径、样本、边界、复现
- 配置/安装：doctor、真实加载、权限、回滚
- 交付：验收标准逐条对照

**失败处理**：同一问题两次失败 → 停止重试，收集证据，换方案或回问。外部写入结果不明 → 先核验，不重复。

## 7. 沉淀（Learn）

- 只记录长期价值：流程、命令、路径、决策、教训
- 去重：先搜再写；相同结论更新
- 位置：项目记忆 / `knowledge/` / 技能库（procedure）
- 不记录：临时结果、一次性路径、未验证猜测、密钥
- 定期蒸馏，防止膨胀

## 8. 决策矩阵（质量 vs 成本）

| 场景 | 建议 |
|---|---|
| 需求明确、单文件 | 直接做，最小验证 |
| 多文件、有测试 | 计划 + 分步 + 集成测试 |
| 方案不确定 | 先检索 2-3 个候选，比较后选 |
| 高风险/不可逆 | 快照 + 小范围试验 + 明确授权 |
| 长任务/多 Agent | 任务板 + 写域隔离 + 阶段验收 |
| 重复流程 | 固化为脚本/技能，减少人工 |
| 信息密集 | 先结构化摘要，再按需读原文 |
| 成本敏感 | 先减重复与返工，不牺牲关键验证 |

## 9. 验收模板

```markdown
## 验收
- [ ] 需求 1：证据（命令/输出/文件:行）
- [ ] 需求 2：证据
- [ ] 边界/失败路径：证据
- [ ] 回归：命令与结果
- [ ] 回滚：快照/步骤，是否演练
- [ ] 未检查项：明确列出
```

## 10. 常见失败模式

| 症状 | 根因 | 对策 |
|---|---|---|
| 反复改同一处 | 没定位根因 | 先复现、读错误、加日志 |
| 测试通过但线上失败 | 验收环境不真实 | 增加集成/真实运行验证 |
| 交付被退回 | 验收标准未对齐 | 开始前复述标准，阶段确认 |
| Token 爆 | 读了太多无关内容 | 先索引/检索，再按需读 |
| 工具调用过多 | 没有计划 | 先列步骤，合并可并行调用 |
| 规则冲突 | 优先级不清 | 按 precedence.md，记录决策 |
| 升级后坏 | 无快照/未回归 | snapshot + doctor + 回滚演练 |
